# 当前执行顺序：先代理链，后三个去广告试点

2026-11-23 更新：已解析用户提供的最新 Quantumult X 导出。原文件和所有凭据仅保留在本机。暂不全面移植其中的去广告、搜索、跳转或其他功能。

## 现在：只导入第一份单链配置

1. 查看手机 Egern 的版本号及 Pro 状态。当前模板建议 2.20.0 或更新；安装版本尚未确认。
2. 备份手机现有 Egern 配置，导入本机已填入真实参数的 `Egern_01_SingleChain.yaml`。GitHub 上同名文件是无效示例模板，需本机渲染后才能使用。
3. 确认 `AI-Mars` 选中 `Mars-via-A`，该节点 `prev_hop` 是 `Upstream-A`。此阶段无去广告模块，不需要 MITM 证书。
4. 启动 Egern；用 Safari 新开 https://api.ipify.org/ 和 https://www.cloudflare.com/cdn-cgi/trace ，在本机核对 Mars 出口。
5. 查看请求详情：确认命中 `AI-Mars`、最终 `Mars-via-A`，再核对其前置 `Upstream-A`。若当前版本日志未显示整个链，不凭一个策略名称宣称双跳运行路径已完全证明。
6. 实际打开常用 AI，发送一个较长问题，检查流式回答能正常结束。记录时间、成功/失败、无凭据的错误信息；不公开 IP、账号、密码或完整配置。

这里的通过条件是：能导入并启动、路由和前置正确、出口符合 Mars、实际 AI 流式请求成功。桌面首页 HTTP 200 不替代这些步骤。

## 单链通过后：增加备用前置

再导入本机 `Egern_02_Fallback.yaml`，依次手动测试完整 A/B 链，然后选 `Mars-Fallback`。两个候选都带机场前置并连接同一个 Mars，没有 DIRECT、单独机场或直连 Mars 候选。

在备份后的测试副本中让 A 前置不可达，确认转 B 后仍为 Mars；再令两份 Mars 都不可达，确认 AI 与指定出口查询明确失败。检查 Wi-Fi/蜂窝切换、锁屏恢复和已有流式连接。切换会关闭旧连接，可能需要重新发起回答，不能保证无缝续接。

## 链路验收后：仅三个去广告试点

顺序：微博 → 淘宝 → 哔哩哔哩。每个独立模块先单独验证广告位置，以及登录、图片、视频、普通内容和相关业务；淘宝还检查搜索、商品详情与购物车。通过后再组合运行，出问题可以单独停用。

这三个范围由用户明确指定；微博与 B 站有导出中的专用资源，淘宝需要从聚合广告资源中抽取清晰的广告接口。适配时只保留广告处理，不带会员、画质权限、下载解锁或页面功能改造。

三者未验收前，暂停其他 App、小程序和整包广告集合的铺开。仓库中的通用广告模板是预备文件，当前导入入口仍是第一份单链配置。
