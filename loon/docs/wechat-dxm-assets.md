# 微信通用广告素材补充

当前版本：v0.7.0，2026-10-30。原 v0.6.0 的度小满四素材规则已升级为路径匹配；文档地址保持不变。

## 本版能处理什么

| 类型 | 主机及范围 | 返回 |
| --- | --- | --- |
| 图片素材 | `wximg.wxs.qq.com`，两段数字目录后的 `snscosdownload/SH或SZ/reserved/`，限定图片文件名格式 | HTTP 200、1×1 GIF |
| 广告视频 | `wxsmw.wxs.qq.com`，两段数字目录后的 `snssvpdownload/SH或SZ/reserved/`，文件名必须以 `ads_svp_video__` 开头且以 `.mp4` 结尾 | HTTP 200、空白视频 |

图片 ID、品牌及查询参数不再固定，覆盖同类路径下更换的广告素材和已支持的图片变体。两条规则使用完整主机及路径边界；没有将 `wxs.qq.com`、微信图片域名或微信通信通道整体拒绝。

这是素材层的通用化，未找到能在这份抓包中可靠修改的通用广告卡片数据接口。因此不能承诺公众号、朋友圈、所有小程序或激励视频全面去广告，也不保证文字、按钮、卡片高度和空白占位消失。

## 依据与取舍

- 图片路径形态来自用户样本与公开的[晴雅广告过滤器 black.txt](https://github.com/rssvcn/qy-Ads-Rule/blob/96983348e91a488d605c11c9e13c37c6cab838e2/black.txt)，V1.8.6，Git blob `7991003f682a6cc40dd1ee42c1176a21d5a6b067`。其有按 `snscosdownload/.../reserved` 处理微信资源的规则。本版仅采用路径思路并收窄到已见主机、目录和文件名形式；没有照搬其整域名列表。Loon 此处按 URL 判断，没有移植原过滤器的进程限定语法。
- 视频来源于同一份抓包：素材路径有明确的 `ads_svp_video__` 前缀，解码首帧也显示游戏广告标识。这给出了超出度小满品牌的广告样本。
- 图片通用规则仍是路径归纳，不是腾讯官方声明每个路径资源均为广告；在未取得正文的记录上，仅能确认路径匹配，不能确认每个资源内容。
- [217heidai/adblockfilters #178](https://github.com/217heidai/adblockfilters/issues/178) 有用户反馈整域名屏蔽后正常聊天图片加载缓慢，维护者随后放行。因此本版没有采用整域名屏蔽。这一反馈也不能证明本版更窄的路径规则绝无误伤。
- 墨鱼的 [Applet.conf](https://github.com/ddgksf2013/Rewrite/blob/master/AdBlock/Applet.conf) 明确只针对特定小程序；其公众号 `getappmsgad` 处理在奶思已有相近覆盖，本版没有重复叠加。
- 占位媒体响应采用 [Loon Rewrite v2 官方语法](https://nsloon.app/docs/Rewrite/rewrite_v2/)的 `reject_img(200)` 和 `reject_video(200)`。这改变响应内容与状态，不保证客户端不会尝试其他广告来源。

`mp.weixin.qq.com/mp/getainfo` 在样本中返回 `LINK_TYPE_MP_APPMSG` 文章链接信息，没有将其误当广告列表清空。普通文章图片、头像、语音、文章接口及微信二进制通信没有新增规则。

## 验证结果

同一份私有抓包包含 583 条请求：

- 原 v0.6.0 规则匹配 6 次请求，涉及 4 个已目视确认的度小满素材路径。
- v0.7.0 匹配 16 次请求：14 次图片、2 次广告视频，共 13 个不同路径；原 6 次仍全部匹配。
- 其余 567 条不匹配这两条规则。
- 命中的记录中有 5 张图片及 2 段视频响应可检查；一个视频响应只有 2 字节，其余部分记录没有正文。这些数字不能等同于已确认移除 16 个广告。

本地回放只执行 URL 匹配，没有重发抓包请求。公开测试只保留早前已公开的共享素材标识和新的合成地址，不包含真实查询参数、Cookie、Token 或原始请求头。

全套 61 项离线测试通过，其中微信 8 项，覆盖旧素材回归、新 ID 和变体、视频广告前缀、普通业务路径、主机/查询误匹配、开关关闭、与固定奶思 V2 的静态重叠检查。其他应用的 47 条处理指令、所有响应脚本代码和微博分流保持不变。没有运行 Loon 官方解析器或更新后手机实测。

## 更新、验证和回退

1. 更新原来的「Shiina 去广告补充（V2）」，确认描述显示 v0.7.0。
2. 开关现在显示为「微信通用广告素材」，底层仍为 `wechat_dxm_assets`，继承以前保存的开关状态。首次安装默认开启；此前关掉过的需手动打开。
3. 确保 MitM 和证书信任正常。退出小程序或文章页后重新打开，确认新请求是否命中两类素材规则。
4. 新响应是 HTTP 200 占位媒体，只看错误/拒绝列表可能不足；需查看具体请求的复写信息或返回媒体。
5. 同时验证普通聊天图片、文章图片、视频和常用小程序功能。异常时关闭「微信通用广告素材」对照；开关停用复写，但精确 MitM 条目仍在。完整停用本插件需关闭整个 Shiina 补充。

如果仍有广告，新抓包可区分缓存、相同路径未命中、新域名/目录、以及图片已被替换但卡片占位仍在。未来同目录混入非广告资源可能误伤，需要依据新样本收窄；不会因广告仍在就直接屏蔽整个微信图片服务。

原始 ZIP、素材图片、请求凭据及个人网络配置不进入公开仓库。
