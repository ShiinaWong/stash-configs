# 微博国际版补充 v0.2.0

## 本次确认的情况

2026-10-26 的抓包包含 101 组会话、84 个原始响应正文。请求产品标识为 WeiboOverseas/7.2.2 和 Weibo intl./7.2.2.1。此处只记录通用接口、结构和统计，不保存抓包、完整请求 URL、正文或用户标识。

| 目标 | 观察 | 本版处理 |
| --- | --- | --- |
| POST `bootpreload.uve.weibo.com/v1/ad/preload` | 两次成功响应的 ads 数组分别包含 16、15 条广告 | 只清空 ads，保留 code 与其他配置 |
| GET `weibointl.api.weibo.cn/portal.php?a=get_coopen_ads` | display_ad=1，pic_ad 1 项，gdt_video_ad_ios 2 项，ad_list 为空 | display_ad=0；清空已存在的上述三个广告数组 |
| GET `weibointl.api.weibo.cn/portal.php?a=open_app` | 五个广告字段为 1 | 将这五个字段改为 0，保留其他设置 |

五个字段为：`uve_feed_ad`、`uve_hot_ad`、`new_ad_status_timeline`、`new_ad_status_search`、`new_ad_status_hot`。这些字段与广告开关的关系根据捕获结构及命名判断；客户端是否实际遵从修改需要真机确认。本版不改 `uve_feed_ad_block` 等语义可能相反或不确定的字段，不删除微博帖子。

本次没有捕获 friends_timeline / cardlist 等含信息流卡片的返回正文，不能据此声称已定位全部信息流广告。采集到的普通图片、长文请求与曝光统计也不等于广告供给接口，因此没有一并拦截。

## 为什么作为奶思的补充

比对日期：2026-10-26。

- 已检查 fmz200/wool_scripts 的 `Loon/plugin/blockAdsV2.plugin`，Git blob SHA：`0eeb11f1fe45618966ba3d4a2f7c6d9c86b1ee45`。
- 大合集中的 Weico 条目匹配 `overseas.weico.cc/portal.php?a=get_coopen_ads`；本次客户端访问的是 `weibointl.api.weibo.cn`，主机不同。
- 该大合集没有覆盖本版的开屏预加载接口和 open_app 广告字段处理。
- 作者另有独立 `weibo.plugin`，其中存在开屏处理与更广泛净化。这与大合集是两个订阅，不应混为一谈。本模块只补当前需要的三个接口。
- 若同时启用独立微博专用插件，先检查重叠。Loon 同一响应最多选一条 Response Script，不能假设多个脚本必然依次执行。
- 原始响应不是手机最终显示的证据；本抓包不含目标响应的替换正文和完整规则命中信息，不能仅凭原始 HTTP 200 认定某插件运行报错。这里确认的是上游范围差异和可处理的数据结构。

## 启用与验证

1. 更新已安装的「Shiina 去广告补充（V2）」订阅，确认描述显示 v0.2.0；首次使用可从 [主说明](../README.md) 导入。
2. 插件的「微博国际版补充」默认开启；「微博国际版信息流广告开关」默认开启，只控制 open_app 处理。保持 Loon MitM 可用，不需要启用抓包录制。
3. 退出微博国际版再启动，等待配置请求完成，再测试一次冷启动和信息流刷新。首次打开可能仍使用此前缓存的广告或配置。
4. 有内置清理缓存功能时可用于处理旧广告缓存；不要求先卸载 App 或清除账户数据。
5. 检查首页正常微博、图片、长文、视频、评论及登录状态。信息流若仍有广告，应采集刷新/滚动加载时对应的时间线响应和广告位置，再做下一轮分析。

脚本日志只输出固定路由名与修改字段数量：
`[Shiina Weibo Intl] splash`、`ad-config`、`feed-config`。
它们证明脚本执行并改变了字段，不证明客户端最终不显示广告；没有修改的响应不输出该日志。

## 回退

- 若只在修改配置后出现异常，先关闭「微博国际版信息流广告开关」。
- 完整回退时停用补充插件并重新启动 App 获取原配置；插件停用不会主动删除 App 已缓存的响应。
- 插件参数开关不移除 MitM 主机。停用整个补充插件，才撤销它新增的主机条目（其他插件仍可能声明相同主机）。
